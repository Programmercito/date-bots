# club-like-processing Specification

## Purpose

Process likes generated by the discovery flow: persist them, detect mutual matches, handle unavailable targets, and notify the target user when the like is not mutual.

## Requirements

### Requirement: Persist Like

The system MUST persist a `Like` row with `from_chatid`, `to_chatid`, `matched=false`, and the current timestamp when a `LikeMessage` is consumed from `queue.like`.

#### Scenario: First like is persisted

- GIVEN user A has an APPROVED profile
- WHEN a `LikeMessage` from A to B arrives on `queue.like`
- THEN a `Like` row is saved with `from_chatid=A`, `to_chatid=B`, and `matched=false`

### Requirement: Detect Mutual Match

The system MUST check for an existing like from the target back to the liker inside the same transaction. If the reverse like exists, the system MUST mark both rows as `matched=true` and enqueue a `MatchMessage` to `queue.match`.

#### Scenario: Mutual like creates a match

- GIVEN user A already liked user B
- WHEN a `LikeMessage` from B to A arrives on `queue.like`
- THEN both like rows are marked `matched=true`
- AND a `MatchMessage` with A and B is sent to `queue.match`

### Requirement: Anonymous Non-Mutual Notification

If no reverse like exists, the system SHOULD send an anonymous notification to the target user indicating that someone liked their profile.

#### Scenario: Anonymous like notification

- GIVEN user A likes user B and B has not liked A
- WHEN the like is processed
- THEN B receives a message stating someone liked them, without revealing A's identity

### Requirement: Unavailable Target

If the target profile status is `REJECTED` or `PAUSED`, or the target user is blocked, the system MUST notify the liker and MUST NOT persist the like.

#### Scenario: Liked profile was paused

- GIVEN user B's profile status is `PAUSED`
- WHEN user A likes user B
- THEN A receives a notification that the profile is unavailable
- AND no `Like` row is created

### Requirement: Duplicate Like

If a like from the same `from_chatid` to the same `to_chatid` already exists, the system MUST ignore the duplicate without raising an error.

#### Scenario: Double tap on like button

- GIVEN user A already has a persisted like to user B
- WHEN another `LikeMessage` from A to B arrives
- THEN the existing row remains unchanged
- AND no duplicate row is created
